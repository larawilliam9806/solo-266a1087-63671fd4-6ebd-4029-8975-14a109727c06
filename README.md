# 地方台网历史地震目录归档与波形调阅

按 UTC 日期从地方台网的历史目录接口采集地震事件，逐日跟踪查全进度，支持为无法通过接口查全的日期补档全日 CSV，并在全部日期查全后导出完整目录。在此基础上，可按台站与 UTC 日管理冷存储波形索引，并为归档任务生成波形调阅清单：复核人员据此知道该取哪些文件、各截哪一段。

## 功能

### 目录归档

- 选择最多 **31 个连续 UTC 日** 建立归档任务。
- 接口按“日期段”返回事件列表，每次最多 **20 条**：
  - 返回不足 20 条 → 该段已查尽，段内**每一天**都记为“已查全”（零条的日子也算）。
  - 返回满 20 条 → 段内可能还有事件，把日期段对半拆开继续查询。
  - 拆到单日仍满 20 条 → 该日标记为“待补档”，已取到的首页记录先入库。
- 页面按天列出进度：待查询 / 已查全 / 待补档 / 待重试，并显示条数与最近更新时间。
- 请求失败的日子记为“待重试”。点击“采集 / 重试”只会重查“待查询”和“待重试”的日期，**不会**重复请求已查全、待补档的日期。
- 待补档日可上传全日 CSV：
  - 文件必须只包含该天（UTC）的事件；
  - 事件编号在文件内唯一，且不能与其他日期已归档的编号冲突；
  - 接口已采到的记录必须**逐条原样**出现在 CSV 中（编号、时刻、震级都一致）；
  - 任一校验失败都不会改动已有进度（补档写入在单个事务中，失败自动回滚）。
- 只有当任务内**每一天**都是“已查全”或补档成功后才允许下载完整目录（否则下载入口返回任务页并提示）。

### 波形索引（按台站 + UTC 日）

- 在“波形索引”页按台站和 UTC 日上传或替换索引 CSV，每行记录**分量（Z、N、E）、文件编号、UTC 起止整秒**。
- 规则：
  - 文件从所选 UTC 日开始，最长 24 小时，**可跨午夜**；
  - 所有区间均为**左闭右开**；
  - 文件编号在同一台站内唯一（跨日也不能复用），同一文件编号各分量的起止时刻必须一致；
  - 仅含表头的 CSV 合法，保存后**清空该日索引**；
  - 校验失败或保存失败时，本次变更前的索引、清单与归档进度全部保留。
- 替换索引时只重算**与换入或换出文件时段相交**的清单窗口，且范围**限于该台站**，其他台站的清单不动。

### 波形调阅清单

- 在归档任务中选择一个台站生成调阅清单，核对**已查全日期**内每个事件**发震前 30 秒到发震后 90 秒**（左闭右开）的三分量波形。
- 三分量均连续覆盖时，按分量列出所需的**最少文件**及各自截取范围（最小区间覆盖贪心算法；同分量的截取段互不重叠）。
- 覆盖不足时按分量列出**缺段**（同样为左闭右开整秒区间），并保留已有覆盖片段。
- 清单页面直接读取数据库中**已保存**的清单内容，不做现场重算。
- 清单可启用/停用：**启用后**，采集或补档使某日查全时，该日事件与调阅窗口在**同一数据库事务**中一起生效（任一步失败则整体回滚）；停用清单保留内容但不再随采集自动更新。

```
scripts/make_backfill.py      # 生成演示用单日补档 CSV
scripts/make_wave_index.py    # 生成演示用波形索引 CSV（全覆盖 / 含缺段）

seed/backfill_2024-03-12.csv               # 演示用单日补档 CSV（27 条）

tests/test_waveform.py       # 波形索引、规划器、增量重算与事务测试
Dockerfile, docker-compose.yml, docker-entrypoint.sh
```

## 用 docker compose 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

首次启动会把 `seed/` 下的模拟目录复制到数据卷中作为模拟接口的数据源，之后持久化在 `archive-data` 卷里（`/data/archive.db` 为归档库）。

演示流程：

1. 新建任务，例如 `2024-03-01` ~ `2024-03-03`，点击“采集 / 重试”。
   - 大部分日期会被判为“已查全”（含零事件的日子）；
   - `2024-03-12` 有 27 条，单日满页，显示为“待补档”；
   - 想演示“待重试”，可设置环境变量 `MOCK_FAIL_DATES=2024-03-18` 后启动，采集时该日会失败，清空该变量重启后再次点击“采集 / 重试”即可。
2. 打开“波形索引”，新建台站 `STA01`，在台站页选择 `2024-03-01` 并上传 `seed/wave_STA01_2024-03-01_full.csv`；再上传 `..._gap.csv` 可观察 Z 分量缺段如何反映到清单中（仅含表头的 CSV 则清空该日索引）。
3. 回到任务页，选择台站 `STA01` 点击“生成 / 重算调阅清单”，查看每个事件三分量的最少文件与截取范围，或覆盖不足时的缺段。
4. 点击“启用清单”，之后对 `2024-03-12` 上传 `seed/backfill_2024-03-12.csv` 完成补档：该日事件与清单窗口在同一事务中一起出现。
5. 全部查全后，“下载完整目录”按钮可用，导出 CSV（`event_id,utc_time,magnitude`）。

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DATABASE` | `/data/archive.db` | SQLite 数据库路径 |
| `CATALOG_FILE` | `/data/catalog.json` | 模拟目录数据文件 |
| `MOCK_FAIL_DATES` | 空 | 逗号分隔的日期，模拟接口在这些日期所在区间返回失败 |
| `SECRET_KEY` | `dev-only-change-me` | Flask 会话密钥 |

## 采集规则要点

采集器把待查日期按连续区间分组，每组最长 31 天，然后从整段开始递归：

```
fetch(段) -> 不足 20 条：段内每天记为已查全（写入返回的事件）
           -> 满 20 条且段 > 1 天：对半拆分，分别 fetch
           -> 满 20 条且段 = 1 天：该日记为待补档（保留首页 20 条）
```

对接口返回的越界事件（不在请求区间内）或超过 20 条的响应，按请求失败处理，不会把错误数据写入其他日期。

## 调阅规划与一致性要点

- 每个事件窗口为 `[发震时刻-30s, 发震时刻+90s)`，按 Z/N/E 三个分量分别规划；文件区间与截取区间一律左闭右开、单位为整秒。
- 最小区间覆盖贪心：在窗口游标处选择“起点不晚于游标且终点最远”的文件，确定性地打破并列（文件编号较小者优先），因此同一索引总产生同一份清单。
- 索引替换的重算范围 = 该台站所有清单中，与任一换入/换出文件区间时间相交的窗口；不相交窗口与其他台站清单保持原样。
- 启用清单的自动同步挂在采集查全（`complete_days`）与补档查全（`backfill_day`）的事务内：事件写入、日期状态变更与窗口写入同生共死。
- 索引校验、文件编号冲突或任一保存失败都会回滚所在事务，归档进度、索引与清单回到变更前状态。

## 接入真实接口

`archive_app/catalog.py` 中的 `CatalogSource` 是唯一需要替换的抽象：实现 `fetch_page(start, end) -> list[Event]`（最多返回 20 条，失败抛 `SourceError`），并在 `source_from_env()` 中返回它即可。采集、进度、补档、波形索引与调阅清单逻辑与数据源无关。
